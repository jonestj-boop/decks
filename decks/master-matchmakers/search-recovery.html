Finding one

51 of the 64 location pages exist in Google's index twice

Each city page has a second address left over from an older version of the site, capitalised rather than lowercase. Both versions are indexed. Both rank. They rank at different positions for the same searches, which means every one of these pages is competing against itself.

Finding one, in one page

St. Louis is on page one of Google twice, and takes 15 clicks

The clearest single illustration. Two addresses for the same city page, both averaging page one, both shown thousands of times, both almost never clicked. They are not losing to a competitor. They are splitting the same search between them.

What this costs
  • 6,586 impressions across the two, and 15 clicks between them.
  • A page averaging position 8 would normally return several percent. These return a quarter of one percent.
  • Everything that would push one page up, links, relevance, engagement, is being divided across two.
  • The same pattern repeats on 50 more pages.
Why it has not resolved on its own

The redirect from the old address to the new one is already in place, and the page carries the correct canonical tag. The pieces that should have consolidated these are there.

What keeps the old address alive is that links inside the site still point at it. Google keeps rediscovering a URL the site itself still references, so it keeps it indexed. That is a fixable problem, but it is a sweep across the site rather than a single setting.

Finding two

75 referring domains are being delivered to the wrong page

Other websites have linked to Master Matchmakers city pages for years, using addresses like /AboutUs/NewYork. Every one of those redirects to the generic About Us page instead of the city page it names. A redirect onto an unrelated page is commonly treated as a dead end, so that authority is not reaching anything.

How this was checked

Two findings did not survive verification, which is why we trust the three that did

Every number in this deck was confirmed against the live site rather than read off a report. That process removed as much as it produced.

Withdrawn
The backlink export showed the http version of the homepage returning a 403 error with 157 referring domains behind it, which read like a large amount of authority hitting a wall. Requested live, it returns a clean redirect. The error was the reporting tool being blocked, not the site.
Withdrawn
We initially believed the duplicate pages lacked canonical tags, which would have explained everything neatly. Checking ten of them live showed the tags are present and correct. The real cause is internal links still pointing at the old addresses, which is a different fix.
Confirmed
The duplicate index entries, the misrouted referring domains, and the click-through spread on page-one pages were each verified individually. The redirect destinations in this deck were read from live response headers, one URL at a time.
